2026-08-14 - Policy Document Management
- Added tenant-scoped policy document library backed by MongoDB metadata.
- Added document versioning by tenant and policy filename.
- Added active, archived, processing, and failed policy states.
- Added archive, restore, and permanent delete endpoints.
- Added Qdrant payload metadata for document_id, document_version, and policy_status.
- Archived/failed/processing vectors are excluded from HR policy retrieval.
- Added admin dashboard policy document table with search/status filters and actions.
- Added document counts and active/archived/failed statistics to admin overview.
2026-08-14 - Fix Qdrant policy retrieval metadata filters
- LangChain Qdrant stores Document.metadata under the `metadata` payload key.
- Tenant/document/status filters now use metadata.tenant_id, metadata.document_id, and metadata.policy_status.
- Policy chunk counts in the admin dashboard now use the same correct filter.
- Archive, restore, and delete update/delete the actual LangChain metadata payload.
- Legacy migration helper now writes tenant_id into metadata.

2026-08-14 - Backward-compatible Qdrant tenant filtering
- Policy retrieval and dashboard counts now accept both metadata.tenant_id and legacy top-level tenant_id payload layouts.
- Policy lifecycle operations accept both metadata.document_id and legacy document_id layouts.
- Explicit archived/processing/failed policies are excluded in either payload layout.
- Points without a tenant ID are never returned, preserving tenant isolation.
2026-08-16
- Prevent archived/deleted policy documents from being used as fresh knowledge-base evidence.
- Policy retrieval now requires an explicit active status, including for legacy payload layouts.
- Existing sessions no longer feed previous assistant answers/tool outputs back to the LLM as authoritative context.
- Recent user questions are retained for conversational continuity, while current-turn tool messages remain available.
- Archived documents can remain visible in historical chat UI, but cannot be cited or reused as current KB evidence.

2026-08-16 - Non-blocking policy indexing lifecycle
- Policy uploads now return immediately with status `indexing` instead of waiting for embeddings/vector writes to finish.
- New uploads are indexed in small Qdrant batches and Mongo tracks `total_chunks`, `indexed_chunks`, and `progress`.
- A document cannot become `active` until every chunk has been successfully indexed.
- The previous active version remains searchable while a replacement version is indexing.
- Failed/partially indexed uploads are deleted from Qdrant and marked `failed` in Mongo.
- Qdrant retrieval continues to require explicit `policy_status=active`, so indexing/archived/failed vectors are never used as current KB evidence.
- Admin document library now polls indexing progress and displays `indexed / total` chunks plus a progress bar.
